## 3. 设计要点（架构决策记录）

1. **异步化**：v2 运行不再由 HTTP 请求生命周期绑定（v1 依赖 res close 中断）；创建即 202 返回，状态经 SSE 推送。
2. **事件溯源式 UI**：前端只消费事件流（计划/步骤/工具/审批/终态），断线重连由 EventSource 自动完成，服务端回放历史事件。
3. **审批双通道**：DB（approvals 表）为审计权威；内存 ApprovalStore 负责唤醒等待中的 Loop；DB 行 id 与内存 PendingApproval 通过 runId+toolName 关联。
4. **持久化非阻塞**：store 全部经 `silent()` 包装，落库失败仅记日志，不影响 Agent 运行（Phase 1 取舍，后续 tasks 队列补强）。
5. **三处 Schema 同步**：新增表 = 迁移 SQL + schema.prisma + fieldmaps.ts；`SCHEMA_SQL` 保持基线不动（Phase 0 约定）。
6. **权限解析**：v2 复用 v1 normalize/resolve（allow/ask/deny + 默认策略），`resolveToolPermission` 为 Phase 2 的 user/agent/tool 三级策略预留唯一入口。

## 4. 遗留与风险

- `npm run server:build`（tsc）仍有**既有**错误（测试文件 .ts 导入 + 3 个旧生产文件未用变量），与本次无关，建议后续修 `server/tsconfig.json` 的 `allowImportingTsExtensions` 或清理旧文件。
- SSE 事件与回放之间存在毫秒级竞态（先回放后订阅），客户端以最终 GET 状态为准，可接受。
- approvals 内存/DB 双写：进程重启后未决审批丢失（等待中的 run 也会中止），Phase 2 的 tasks 队列 + 审批重启恢复解决。
- 前端 V2 面板为最小可用版（无历史会话页集成），Phase 2 工具管理页时一并完善。
