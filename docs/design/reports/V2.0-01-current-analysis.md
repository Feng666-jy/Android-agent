**关键事实**：
- 项目**当前不是原生 Android 应用**，而是移动风格 Web 应用（Vue3）+ Node 后端；`docs/design/PHASE4-REPORT.md` 提到 Capacitor 打包 APK 的"接缝"（fetch 可注入、node:sqlite 零原生依赖），但**尚未实现 Android 工程**。
- 运行时数据库是 **node:sqlite + 手写 Prisma 兼容层**（`SCHEMA_SQL` + `CREATE TABLE IF NOT EXISTS` 幂等建表），`prisma/` 仅保留 Schema/迁移定义；**当前无 ALTER TABLE 迁移能力**。
- `package.json` 中没有 `@prisma/client` / `prisma` 运行时依赖（只有 schema 与 CLI 用法）。

## 5. 当前架构的核心问题（升级动因）

1. **Agent 是一次性长任务，不是持续会话**：无 conversations/messages 实体，无法多轮续聊、分支、跨会话记忆。
2. **无"设备"概念**：一切工具都是服务器本地（sandbox），Android 设备能力无从挂载。
3. **权限策略无状态**：审批在内存，重启丢失、多实例失效、无审计。
4. **无扩展层**：工具/MCP/Skill 全部硬编码，商业化（市场/插件）无基础。
5. **同步阻塞模型**：长任务体验差，无进度流、暂停/恢复。
6. **双 Schema 风险**：`prisma/schema.prisma` 与 `server/src/db/schema.ts` 靠人工同步；未来加表必须引入真正的迁移运行器。
