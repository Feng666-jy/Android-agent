# 《开发路线图 + Android Agent V2.0 开发任务列表》

> 原则：不一次性重构；每阶段可独立交付、可回滚；v1 与 v2 并存直至切换完成。

---

## 路线图总览

```
Phase 0 修复基础架构   → Phase 1 Agent Core 升级
                              ↓
                        Phase 2 Tool 系统
                              ↓
                        Phase 3 Android Runtime
                              ↓
                        Phase 4 Memory + Workflow
                              ↓
                        Phase 5 商业化能力
```

---

## Phase 0 — 修复基础架构（1~2 周）

**目标**：消除"双 Schema 人工同步 + 无迁移能力"的基础风险，为后续加表铺路。
**修改文件**：`scripts/migrate.ts`(新)、`prisma/schema.prisma`、`server/src/db/schema.ts`、`server/src/db/fieldmaps.ts`、`package.json`、`.codex/memory.md`、`.codex/database.md`
**新增模块**：迁移运行器（_migrations 表 + 幂等 ALTER 检查）
**验证**：对现有 dev.db 执行迁移，行数不变；`npm test` 全绿
**风险**：低。迁移器误操作会伤数据 → 先备份 dev.db + 只做增量 + PRAGMA 检查

## Phase 1 — Agent Core 升级（2~3 周）

**目标**：从"一次同步长任务"升级为"会话 + 计划 + 步骤 + 事件流"。
**修改文件**：`server/src/services/agent/*`（演进为 agent-v2）、`controllers/routes`、`src/api/agent.ts`、`src/components/ai-home/AgentRunPanel.vue`、`src/stores/conversation.ts`
**新增模块**：`services/agent-v2/`（planner/loop/context/events/steps/permissions-v2）、`routes/v2/`
**验证**：POST /api/v2/agent/runs + SSE events 端到端；旧 /api/agent/run 不受影响
**风险**：中。会话模型重构（conversations/messages 落库）会牵扯前端历史页 —— 先加表再切 UI

## Phase 2 — Tool 系统（2~3 周）

**目标**：工具动态化 + 权限落库 + MCP + Skill。
**修改文件**：`server/src/services/agent-v2/tool-router.ts`、`permissions-v2.ts`、`server/src/services/agent/tool-registry.ts`（迁移）、`src/views/`（工具管理页）
**新增模块**：`services/mcp/`（client/registry/adapters）、`services/skills/`（loader/injector）、`approvals` 表落库
**验证**：tools 表 CRUD + 参数级审批 + MCP demo server（sse）工具调用 + Skill 注入生效
**风险**：中。MCP 协议（OAuth/streamable-http）复杂度高 —— 先支持 SSE 无鉴权 server，OAuth 后置

## Phase 3 — Android Runtime（3~5 周）

**目标**：端侧设备能力 + Device Bridge + Accessibility + Vision。
**修改文件**：`vite.config.ts`（Capacitor 适配）、`package.json`、`server/src/routes/v2/device.routes.ts`
**新增模块**：`android/`（Capacitor 插件工程：NativeToolBridge → AccessibilityEngine → VisionEngine）、`services/android/`（device-registry/bridge/native-tools/a11y-tools/vision-tools）
**验证**：真机/模拟器依次通过 battery → 启动应用 → UI 树 → 点击/输入/滑动 → 截图+VL 理解闭环
**风险**：高。权限引导（无障碍/悬浮窗/MediaProjection）碎片化；建议分 3 个子阶段（P3a 基础工具、P3b Accessibility、P3c Vision）

## Phase 4 — Memory + Workflow（2~3 周）

**目标**：长期记忆 + 自动化工作流。
**修改文件**：`server/src/services/agent-v2/memory.ts`、`server/src/services/workflow/*`
**新增模块**：memories 表 + 记忆工具 + `<memories>` 注入；workflows/workflow_runs 表 + DAG 执行器 + 定时调度（node-cron 或内置 setInterval）
**验证**：跨会话记忆生效（两次对话记住偏好）；创建一个"定时查天气发通知"工作流跑通
**风险**：中。记忆隐私与噪声（默认不存敏感信息）；工作流调试成本 —— 先提供执行日志页

## Phase 5 — 商业化能力（3~4 周）

**目标**：多用户配额、密钥池、限流、审计、计费基础。
**修改文件**：`server/src/services/llm/index.ts`（限流/Key 池）、`middleware/`、`src/views/me/`
**新增模块**：usage 报表（现有 usage_stats 扩展）、RateLimiter、ApiKey 池、配额校验、audit_logs 查询页
**验证**：压测限流生效；账单/用量页数据准确；审批审计可查
**风险**：中。计费精度与合规 —— 先做"用量统计 + 配额限制"，计费后置

## 实施顺序建议

1. 先做 T01–T05（迁移能力 + 会话表）→ 冻结 Schema 风险。
2. 再做 T06–T13（Agent V2 核心闭环，前端可见进度/审批）。
3. T14–T20 工具化（此时 MCP/Skill 可并行）。
4. T21–T28 Android Runtime（需要真机联调，与前端并行）。
5. T29–T34 Memory + Workflow。
6. T35–T40 商业化与收尾。
