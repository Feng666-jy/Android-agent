# 《下一代 Android Agent 架构 V2.0》

> 定位：在现有 Vue3 + Express 基础上演进为"云端 Agent Runtime + 端侧 Android Runtime"的双运行时架构。
> 核心决策：**Agent 大脑（Planner/Loop/Memory/Tool Router）留在 Node 后端**（复用现有投资），**Android 端提供设备执行面**（原生工具 / Accessibility / Vision），通过 Device Bridge 连接 —— 与 Operit 全端侧、RikkaHub 全端侧的路线相比，这是当前代码库成本最低、能力最强的演进路径。

## 2. Android Runtime 设计（三阶段）

### Phase 1：基础工具（NativeToolBridge）

| 能力 | Android API | 权限 | 实现方式 |
|------|-------------|------|----------|
| battery | `BatteryManager` / `ACTION_BATTERY_CHANGED` 广播 | 无（普通权限） | Capacitor 插件读取 level/status/temperature |
| file | `context.filesDir` + SAF（`ACTION_OPEN_DOCUMENT`） | 应用私有目录无需权限；外部存储用 SAF | 封装 list/read/write/upload，与云端 sandbox 工具同构 |
| app launcher | `PackageManager`（queryIntentActivities）+ `startActivity` | 无 | 中文名/包名映射 + 最近使用（UsageStatsManager 可选） |
| notification | `NotificationListenerService`（读）/ `NotificationManager`（发） | `POST_NOTIFICATIONS`(13+) + 通知使用权 | 读取/创建通知、点击通知（pendingIntent） |
| 其他 | `Settings.Global` / `ConnectivityManager` / `ActivityManager` | 视能力 | 亮度/音量/WiFi 状态、前台应用、剪贴板 |

实现骨架（Capacitor 插件，Kotlin）：
```
android/runtime-plugin/src/main/java/.../AndroidRuntimePlugin.kt
  @CapacitorPlugin(name = "AndroidRuntime")
  class AndroidRuntimePlugin : Plugin() {
    @PluginMethod fun battery(call) {...}
    @PluginMethod fun launchApp(call) {...}
    @PluginMethod fun getUiTree(call) {...}   // Phase 2
    @PluginMethod fun screenshot(call) {...}  // Phase 3
  }
```

### Phase 2：Accessibility Agent

| 能力 | Android API | 权限 | 实现方式 |
|------|-------------|------|----------|
| 查找文本 | `AccessibilityNodeInfo.findAccessibilityNodesByText()` | 无障碍服务 | 服务内查询，返回节点列表（text/bounds/clickable） |
| 点击 | `performAction(ACTION_CLICK)` 或 `dispatchGesture(GestureDescription)` | 无障碍服务 | 优先节点级点击，回退坐标点击 |
| 输入 | `ACTION_SET_TEXT` / `ACTION_FOCUS` + 剪贴板粘贴回退 | 无障碍服务 | 复杂输入走"设置文本"，防 IME 干扰 |
| 滑动 | `dispatchGesture`（swipe 手势） | 无障碍服务 | 坐标起止 + 时长 |
| 获取页面结构 | `rootInActiveWindow` → 递归序列化 | 无障碍服务 | 序列化为紧凑 JSON（text/bounds/class/actionable），限深限量（如 500 节点） |
| 返回/Home/最近任务 | `performGlobalAction` | 无障碍服务 | 全局动作 |
| 服务就绪 | `AccessibilityService` 配置 XML + `Settings.ACTION_ACCESSIBILITY_SETTINGS` | 用户手动开启 | 状态机 DISABLED→ENABLED→BROKEN；UI 引导页 |

协议（Device ↔ 云端）：
```
→ { type:"a11y.find", query:"搜索", scope:"visible" }
← { ok:true, nodes:[{id,text,bounds:{x,y,w,h},clickable,checked}], treeHash }
→ { type:"a11y.click", target:"nodeId" | {x,y} }
→ { type:"a11y.input", target:"nodeId", text:"..." }
→ { type:"a11y.swipe", from:{x,y}, to:{x,y}, durationMs:300 }
→ { type:"a11y.back" } / { type:"a11y.home" }
```

### Phase 3：Vision Agent

| 能力 | Android API | 权限 | 实现方式 |
|------|-------------|------|----------|
| 截图 | `MediaProjection` + `ImageReader`（或 API 30+ `takeScreenshot()`） | MediaProjection 用户授权（一次性/持续） | 截图 → PNG base64 → 传给云端 VL 工具 |
| 图片理解 | 复用 LLM Provider 层（现有 4 协议 + 图像 content parts） | — | 云端 `vision_understand(image, prompt)` 工具 |
| 坐标点击 | `dispatchGesture` | 无障碍（或 DEBUGGER 通道） | `vision_click(x,y)` |
| 复杂 APP 操作 | PhoneAgent 式循环 | 上述全部 | 见下方 Vision Loop |

Vision Loop（云端 Planner + 设备执行，借鉴 Operit PhoneAgent）：
```
任务 → [Planner 拆解] → 循环(≤20 步)：
  1. 设备截图（a11y tree 可叠加注入）
  2. 云端 VL 模型理解：描述界面 + 输出动作 do(action=click/input/swipe/launch/back, ...) 或 finish(message)
  3. 权限门 → 设备执行
  4. 观察结果回填 contextHistory
  5. 记忆更新 / 进度事件 → UI
```

## 3. Agent Core 升级设计（第五部分完整方案）

### 3.1 新 Agent Loop

```
User Task
  ↓
Planner Engine ──► Plan { goal, steps[PlanStep], toolsHint }
  ↓
Agent Loop（每 step / 最多 N 步）：
  Context Assembly（system + <memories> + plan + 会话历史 + 工具定义）
    ↓
  LLM（Tool Decision）—— 工具调用 or 最终回答
    ↓
  Permission Gate（DB 策略 + 参数级审批 + HITL ask_user）
    ↓
  Tool Execution（Tool Router → Native / Android / Vision / MCP / Skill）
    ↓
  Observation（结果归一化 + 截断 + 注入）
    ↓
  Memory Update（会话写入 + 长期记忆触发：create/edit/delete）
    ↓
  Checkpoint + Event 广播（step.done / tool.result / token）
    ↓
Final Response（LLM 综合 + 引用步骤）
```

### 3.2 数据结构（核心）

```ts
interface AgentRunV2 {
  id: string; userId: number;
  agentId?: string; conversationId?: string;
  task: string;
  plan: Plan;
  status: "planning"|"running"|"waiting_approval"|"paused"|"completed"|"failed"|"cancelled"|"budget_exceeded";
  steps: AgentStep[];
  messages: ChatMessage[];        // 完整消息时间线（含工具）
  tokenUsed: TokenUsage;
  startedAt: string; finishedAt?: string; error?: string;
}

interface Plan { goal: string; steps: PlanStep[]; }
interface PlanStep { id: string; title: string; description: string; status: "pending"|"running"|"done"|"failed"|"skipped"; }

interface AgentStep {
  id: string; runId: string; seq: number;
  kind: "plan"|"act"|"observe"|"reflect"|"final";
  status: "pending"|"running"|"done"|"failed";
  input: string; output?: string;      // LLM 决策 / 观察结果
  toolCall?: ToolCallRecord;           // 本步工具
  tokens?: TokenUsage; error?: string;
}

// 事件（Event Bus → SSE/WS）
type AgentEvent =
  | { type:"run.created"|"run.done"|"run.error"|"run.cancelled" }
  | { type:"step.started", step: AgentStep }
  | { type:"llm.delta", delta: string }
  | { type:"tool.started"|"tool.result", record: ToolCallRecord }
  | { type:"approval.requested", approval: PendingApprovalV2 }
  | { type:"memory.updated", memoryId: string };
```

### 3.5 关键设计决策

1. **v1 与 v2 并存**：`/api/agent/*` 保留，新代码走 `/api/v2/*`，前端逐步切换；AgentRun 旧表数据可读。
2. **运行实体从"一次任务"升级为"会话+运行"**：conversations/messages 为持久会话；agent_runs 为执行记录并挂 conversationId。
3. **审批落库**（approvals 表）替代内存队列：支持多实例、审计、超时恢复。
4. **事件驱动**：所有进度走 EventBus → SSE/WS；轮询仅作降级。
5. **上下文压缩**：Context Manager 提供 token 预算估算 + 摘要压缩（现有 estimateTokens 升级）。
6. **设备能力声明**：设备注册时上报 capabilities（a11yEnabled/visionEnabled/channels[]），Tool Router 只暴露设备支持的 Android 工具。
