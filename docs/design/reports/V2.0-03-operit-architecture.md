# 《Operit 架构可借鉴部分》

> 来源：github.com/AAswordman/Operit（Android 8.0+，Kotlin + Compose + ObjectBox，本地/云端模型）
> 原则：只提取架构思想与模块设计，不复制业务代码。
> 关键模块：`core/tools/system`（自动化）、`core/tools/agent`（PhoneAgent）、`core/workflow`（工作流）、`api/chat/llmprovider`（Provider 层）、`data/skill`（Skill）。

---

## 1. 手机自动化实现方式

### 1.1 权限通道抽象（最重要）

**核心思想：同一套"能力"，按可用权限通道提供不同实现 —— 能力与通道解耦，自动选择最高可用通道。**

```
AndroidPermissionLevel: STANDARD → ACCESSIBILITY → DEBUGGER(Shizuku) → ADMIN(设备管理员) → ROOT
```

- `ActionListenerFactory.getHighestAvailableListener()` / `ActionListenerFactory.getListener(level)`：按当前设备可用权限自动选择监听器。
- `ActionManager`：统一入口（start/stop、事件回调注册、权限状态 StateFlow）。
- UI 操作监听器实现：`AccessibilityActionListener`（无障碍）、`AdminActionListener`、`RootActionListener`、`DebuggerActionListener`。
- Shell 执行同样分层：`ShellExecutorFactory` → `StandardShellExecutor / AccessibilityShellExecutor / AdminShellExecutor / RootShellExecutor / DebuggerShellExecutor`。
- 权限辅助：`ShizukuAuthorizer` / `ShizukuInstaller`、`RootAuthorizer`、`AccessibilityProviderInstaller`、`AndroidPermissionPreferences`（记录用户首选等级）。

**可借鉴**：V2.0 的 Android Runtime 应定义 `PermissionChannel` 枚举 + `ToolExecutorFactory`（按通道选择执行器），单点实现"无权限也能用的降级路径"。

### 1.2 AccessibilityService 与 UI Tree

- 独立无障碍**服务提供者 APK**（`com.ai.assistance.operit.provider`，AIDL `IAccessibilityProvider` 绑定），主应用通过 `UIHierarchyManager` 绑定获取 UI 树 —— 服务与应用进程隔离，避免主进程被杀导致自动化中断。
- UI 树解析：无障碍服务 dump XML → `XmlPullParser` 解析为简化节点（`SimplifiedUINode` / `OperitNodeInfo`：text/bounds/class/clickable...）供 LLM 使用。
- `UIDebuggerService` 提供调试视图。

### 1.3 自动点击 / 输入 / 滑动

- `ToolImplementations` 基类（`StandardUITools` / Accessibility 版 / Debugger 版）：
  - **点击**：`ACTION_CLICK`（无障碍）或 `dispatchGesture` 坐标手势
  - **输入**：无障碍 `ACTION_SET_TEXT` / 剪贴板粘贴回退
  - **滑动**：`dispatchGesture(GestureDescription)` 坐标滑动
  - 附：应用包名映射表（中文名 → packageName，如"微信"→com.tencent.mm）
- 低权限通道（STANDARD）明确返回"不支持，请开启无障碍/调试权限" —— **能力阶梯降级**。

### 1.4 屏幕理解（截图 + Vision）

- `MediaProjectionCaptureManager`（MediaProjection + ImageReader 截图）。
- `PhoneAgent`（见下）：截图 → 图像链接注入 prompt → 视觉语言模型理解 → 输出动作。
- 进阶：**Shower 虚拟显示**（`ShowerServerManager` / `ShowerController` / `VirtualDisplayManager` / `VirtualDisplayOverlay`）—— 用 DEBUGGER/ROOT 通道在**虚拟屏幕**上运行目标 App，主屏幕可同时显示 Agent 进度 HUD；支持多 agent（`agentId`）并发、暂停/接管（`pauseFlow`）、`PhoneAgentJobRegistry` 取消。

## 2. Agent 任务执行流程（PhoneAgent）

**核心思想：Plan-Act-Observe 的 VLM 循环，输出为可解析的标签化动作指令。**

```
用户任务
  ↓ 首次：task + 截图 + systemPrompt
每步（maxSteps=20）：
  ↓ 截图（MediaProjection / Shower 虚拟屏）
  ↓ 组装 user 消息：[SCREENSHOT] 图片链接 + 屏幕信息
  ↓ LLM 流式响应（stream=true, thinking 可选）
  ↓ 解析：<think>推理</think> + do(action=Launch/Swipe/Back/Click/Input, ...) 或 finish(message=...)
  ↓ 执行动作（ActionHandler → ToolImplementations 按权限通道）
  ↓ 结果追加到 contextHistory（保留思考过程 preserveThinkInHistory）
  ↓ 循环直到 finish 或达到 maxSteps
  ↓ 返回最终 message
```

- `StepResult(success, finished, action, thinking, message)` 每步回调 UI（进度浮层 UIAutomationProgressOverlay，显示 step/maxSteps + 状态文案）。
- 上下文 = `List<Pair<String,String>>`（system/user/assistant 历史对），截图仅注入最近一步（`removeImagesFromLastUserMessage` 清理，防上下文爆炸）。
- 双格式支持：原生 function-calling（`StructuredToolCallBridge`）与提示词式工具描述（`ToolPrompt`）可互转 —— 兼容不支持原生工具调用的模型。
- 暂停/恢复/取消：StateFlow pause + Job 注册表取消。

**可借鉴**：V2.0 的 Android Vision Agent 直接采用"服务端 Planner 循环 + 设备端截图/动作执行 + 标签化动作协议（do(...)/finish(...)）"，协议本身与工具调用格式解耦。

## 3. Skill 系统

- `core/tools/skill`：`SkillManager`（扫描目录、加载包、读 SKILL.md）+ `SkillPackage`（元数据）。
- `data/skill/SkillRepository`：GitHub 安装（owner/repo/ref/subDir）、zip 导入、`SkillVisibilityPreferences`（**AI 可见性开关**）、加载错误收集（`getSkillLoadErrors`）。
- Skill 与 ToolPkg、MCP 统一进"市场"（统一搜索/安装/管理）。

**可借鉴**：Skill = 包管理（安装/更新/删除/可见性/错误上报）+ SKILL.md 注入 + 可选的 JS 实现（QuickJS/示例 examples/）。

## 4. 自动化任务系统（Workflow）

**核心思想：可视化 DAG 工作流 + 可插拔执行器 + 多触发器。**

- `core/workflow/WorkflowExecutor`：解析 `Workflow`（节点 + 连接）为依赖图（`DependencyGraph`：邻接表 + 入度），按拓扑序执行；节点状态 `Pending/Running/Success/Skipped/Failed`；支持重试（`WorkflowExecutionRetryableException`）、执行记录与日志（`WorkflowExecutionRecord/LogEntry`）。
- 节点类型：`TriggerNode / ExecuteNode / LogicNode / ConditionNode / ExtractNode / ParameterValue`（触发、执行工具、逻辑、条件、数据提取、参数变量）。
- `WorkflowScheduler` + `WorkflowWorker`（后台定时调度）+ `WorkflowSchedulerInitializer`。
- 触发器：手动 / 定时 / Tasker / Intent / 语音 / 应用启动；`integrations/`：tasker、intent、http bridge、a2a、externalchat。
- 工具执行器 `AIToolHandler`：统一注册（`ToolRegistration`）、参数校验、`ToolExecutionLimits`（频率/时长限制）、`ToolProgressBus`（进度事件）、`AIToolHook`（钩子）、`ToolPackage`（ToolPkg 插件容器）。

**可借鉴**：V2.0 Workflow 层直接采用 DAG + 节点状态机 + 触发器注册表 + 执行记录落库；`ToolProgressBus` 思想与 Agent 事件流统一。

## 5. Provider / 模型层（顺带）

- `AIService` 接口：`sendMessage(context, chatHistory: List<PromptTurn>, modelParameters, enableThinking, stream, availableTools, token 回调)`，统一返回 `Stream`（流式）。
- `AIServiceFactory` + 大量 Provider 实现（OpenAI / OpenAIResponses / Claude / Gemini / Deepseek / Qwen / Kimi / Mistral / Doubao / Mimo / NousPortal / NvidiaAI / OpenRouter / Ollama / Llama.cpp / MNN）。
- 生产级配套：`ApiKeyProvider`（密钥池）、`RateLimiterRegistry` + `SlidingWindowRateLimiter`、`RequestConcurrencyRegistry`、`LlmRetryPolicy`、`HttpStatusCodeException`、`ModelConfigConnectionTester`、`ModelListFetcher`、`EndpointCompleter`、`UnsafeModelSsl`。
- 本地推理：`:llm/mnn`（MNN）、`:llm/llama`（llama.cpp + GGUF），云端/本地统一 AIService 抽象。

**可借鉴**：V2.0 在现有 4 协议之上补"Embedding + 密钥池 + 限流 + 重试"（Phase 5 商业化）；本地模型可作为远期可选。

## 结论（Operit 对 V2.0 的贡献点）

| 贡献点 | 落地位置 |
|--------|----------|
| 权限通道枚举 + 执行器工厂（Accessibility/Shizuku/Root 分级） | Android Runtime（Phase 2） |
| AccessibilityService 独立进程 + AIDL + UI 树解析 | Android Runtime（Phase 2） |
| 截图 + VLM + 标签化动作（do/finish）+ contextHistory | Vision Agent（Phase 3） |
| 虚拟显示（Shower）做后台自动化 | Vision Agent 进阶（远期） |
| DAG 工作流 + 触发器 + 调度 + 执行日志 | Workflow 层（Phase 4） |
| Skill 包管理 + 可见性 + 错误收集 | Skill 层（Phase 2） |
| 密钥池 / 限流 / 重试 / 并发控制 | LLM Provider 层（Phase 5） |
| 能力阶梯降级（无权限也有基础体验） | 全链路 UX |
